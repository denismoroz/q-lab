# q-lab

Research-лаборатория поиска и отсева торговых стратегий. **Ордеров не ставит никогда** —
исполнение живёт в funding-rate-arbitrage на хосте `10.8.0.5`.

Контекст и решения: `docs/PLAN.md`. Контракт схемы реестра: `docs/REGISTRY.md`. Ночь — таблица
шагов `night/pipeline.yaml` со страницей «Пайплайн» в консоли: `docs/PIPELINE.md`.

## Стек

Python 3.13 + uv · SQLAlchemy 2.0 **синхронный** + Alembic + SQLite · typer · pydantic ·
structlog · FastAPI. Фронт: React 18 + Vite + Tailwind + TanStack Query + Recharts.
pandas/numpy/pyarrow для стенда. Тесты — pytest, линт — ruff.

```bash
uv sync
uv run pytest
uv run ruff check src tests
uv run qlab --help
```

## Правила

- **Вердикты выносит код, а не модель.** Правила — версионируемый YAML, движок правил —
  чистая функция. Агент может предложить метрику, но не вердикт.
- **`trial` пишется всегда**, включая выброшенные прогоны: дефляция считается по
  фактическому числу испытаний.
- **У вердикта всегда есть диапазон данных.** Воскрешение с кладбища — только на
  данных, которых не было в момент отказа.
- **Деньги стратегии и деньги на счёте — разные числа** (решение владельца 2026-10-25:
  «стратегия работает на 90 и должна считать все на 90 43 - это то что еще доступно на
  счету - оно не должно никак фигурировать в расчетах»). Любой процент считается от
  `strategy_capital_usd` книги (`night/paper_books.yaml`), никогда от остатка счёта на
  бирже: свободные деньги, пополнения и выводы в доходность не входят. Остаток счёта
  уместен только там, где речь о запасе до ликвидации. Бюджет FRAB с 2026-10-27 — 120 и пять
  мест (владелец поменял сам на хосте, 2026-10-28: «да я»); правило то же, меняется только число.
  Это правило выполняется и на длинных прогонах стенда: у прогона есть ряд на деньгах стратегии
  (`cap_*`, `docs/CAPITAL_BASE.md`; владелец 2026-10-28: «нужно сравнивать яблоки с яблоками а не с
  апельсинами»); складывать прибыль или склеивать её — **объявленное свойство стратегии**
  (`reinvests_profit`), а не выбор стенда, и два сравниваемых числа всегда на одной основе.
  С 2026-10-29 («Да, и правила») решающие правила (версия 2026-10-29.2) и всё, что видит владелец
  (консоль, утренний отчёт, справки агентов), ведут с числа на деньгах стратегии (`cap_*`,
  `noise_cap_*`); число стенда (доля баланса книги) — мелкой строкой рядом, где отличается.
  С 2026-10-29 («да, по всем рекомендациям, делай») деньги стратегии — ещё и поле её спека
  (`strategy_capital_usd`, у числа есть источник в `sources`): нужный капитал прогона сравнивается
  с ними, а не с общей суммой; общей суммы на стенде нет, исхода «полка» тоже (правила 2026-10-29.3,
  `docs/LADDER.md`, ступень 4).
- **Код — по-английски полностью**: имена, комментарии, докстринги, названия тестов,
  сообщения коммитов, а также `rationale` и комментарии в конфигах правил. Исключение —
  прямые цитаты из русских документов: они сохраняются дословно, перевод цитаты делает
  её недостоверной.
- Документация в `docs/` и досье — по-русски: их читает владелец.
- **Карточки кандидатов и досье пишутся без жаргона** (решение владельца
  2026-10-01): термин объясняется при первом появлении, английские торговые
  слова русскими буквами не используются, у каждой карточки есть пересказ
  простыми словами. Полностью — `cards/SCHEMA.md`, «Правила заполнения».

## Бюджет токенов

Относится к ночному конвейеру, а не к интерактивной работе. Задача одна: **конвейер
не должен за ночь израсходовать всё, оставив владельца без аккаунта.**

- Конвейер работает **по подписке владельца** (решение 2026-09-20), то есть квота общая
  с его интерактивной работой. Гард — единственная защита, обойти его нельзя.
- **Аккаунт — только moroz.denis@gmail.com** (Max 5x), решение владельца 2026-10-28:
  «мне нужно чтобы все запускалось под moroz.denis@gmail.com». Обычный `claude` на этой
  машине вошёл в рабочий аккаунт (Stablepay, Team) и так и остаётся; до 2026-10-28 конвейер
  незаметно тратил именно его. Поэтому q-lab запускает агентов из своего каталога
  настроек `~/.claude-qlab` и перед каждым вызовом сверяет аккаунт с `night/account.yaml`:
  чужой аккаунт — агенты не запускаются, токены не тратятся. Расчёт ёмкости берётся только
  из замеров этого аккаунта. Войти заново: `CLAUDE_CONFIG_DIR=~/.claude-qlab claude auth login`.
- Опасно недельное окно, а не пятичасовое: пятичасовое восстанавливается к утру само,
  недельное сбрасывается раз в неделю, и одна прожорливая ночь блокирует владельца на дни.
- Поэтому потолок на ночь **вычисляется, а не задаётся**:

      потолок_на_ночь = (70% недельного окна − потрачено за неделю) / ночей до сброса

  Он сам замедляется, если предыдущая ночь перебрала, и сам ускоряется в начале недели.
- Перевод процентов окна в токены **калибруется по факту**: перед прогоном и после него
  снимается процент занятости, пара (потрачено токенов, прирост процента) пишется в
  `token_spend`. До накопления данных — консервативная оценка.

  Замеры на Pro-плане, 2026-09-20 (два субагента, слой данных и стенд):

  | потрачено | 5-часовое окно | недельное окно |
  |---|---|---|
  | ~470k токенов | +34 п.п. | +4 п.п. |

  Отсюда ёмкость окон: пятичасовое ≈ 1.4M токенов, недельное ≈ 11.7M. Потолок 70%
  недели ≈ **8M токенов**. Это оценка по одной точке — уточнять каждым прогоном.
  С 2026-10-25 тариф Max 5x: ёмкость примерно в 5 раз больше (недельное ≈ 58M — оценка, не
  замер); гард начинает с осторожного числа Pro и уточняет его по журналу этого аккаунта.
- Упёрлись в лимит посреди ночи — пауза с сохранением состояния и продолжение следующей
  ночью. Падать в этом месте нельзя: это штатный режим, а не сбой.
- Потолки многоуровневые: на прогон, на кандидата, на стадию. Кандидат, съевший свой
  потолок, останавливается — он не занимает бюджет остальных.
- **Вызов агента вне бюджетного гарда невозможен по конструкции** — как и прогон без
  accrual: функция без переданного бюджета падает, а не тратит молча. Забыть про
  бюджет нельзя, можно только явно отказаться от него.
- При исчерпании — чистая остановка с сохранением состояния: следующий прогон
  продолжает, а не начинает заново.
- Порядок урезания, дешёвое и обязательное первым:
  1. перепроверка дозревшего кладбища и здоровье живых стратегий;
  2. реализация и прогон кандидатов, прошедших preflight;
  3. поиск нового — режется первым.
- Расход пишется в `token_spend` по стадиям — ради метрики **цены одного выжившего**.
