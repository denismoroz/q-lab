# График проверки вперёд у прошедшей идеи (2026-10-28)

Владелец: «когда стратегия прошла - добавить для неё график - как она проработала на
forward test. для каждого из этапов».

## Что видно

В консоли на странице идеи, которая прошла все правила (статус `validated` или последний
прогон — «прошла все правила, ждёт решения владельца»), есть блок «Как отработала проверка
вперёд». В нём по графику на каждый этап:

- этап 1 — длинная история Binance, этап 2 — Hyperliquid; если второго этапа нет, график один
  и под ним об этом написано;
- зелёная линия — деньги стратегии день за день после комиссий, в процентах **от денег
  стратегии** (`strategy_capital_usd` книги), не от остатка на счёте; ноль отмечен чертой;
- серая пунктирная — что было бы, если просто держать те же монеты те же дни (поровну,
  без комиссий и фандинга; монета, которую книга держит и спотом, и перпом, считается один
  раз, как спот). Её можно скрыть галочкой над графиками;
- подпись под графиком: этап, даты, дни, итог за период, «в год», худшее падение, и тот же
  итог для «просто держать». Отрезок короче 90 дней показан итогом без пересчёта в год
  (решение владельца 2026-10-25: «минус 34% в год» оказалось 21 днём).

Рисуется та часть, которую читают правила: **проверка вперёд** — с даты фиксации параметров
(`params_fixed_at`), а у стратегии, которая выбирает параметры сама по прошлому, — с её
первого выбора (`docs/FIT_VS_FORWARD.md`). Период подбора не рисуется: его результат ничего
не доказывает.

Идея, которая не прошла или закрыта, графика не получает: страница молчит, API отвечает
«не прошла» с причиной.

## Откуда числа

Ряд по дням хранится в файле `data/forward_series/<номер прогона>.json` (несколько сотен
точек; папка в `.gitignore`, ряд можно построить заново). Пишет его `evaluate_spec` из того
самого расчёта, на котором стоит вердикт, для каждого прогона, чья идея остаётся живой
(маршруты `paper`, `shelf`, `needs-infrastructure`, `needs-forward`); отвергнутые прогоны и
шум для калибровки не пишутся. Файл ничего не решает: ни одно правило и ни один агент его не
читают.

Для прогонов, сделанных до этого, ряд строится повторным расчётом — только процессор, без
сети, без агентов, без нового прогона и без записи в реестр:

```bash
uv run qlab forward-series rebuild                 # все прошедшие идеи, чего нет
uv run qlab forward-series rebuild --idea ID --force
```

Расчёт берёт сохранённый снимок данных прогона и файл спека, **совпадающий с записанным в
реестре** (окно данных может отличаться — ночь двигает его на вчера; изменённый с тех пор
спек не годится), режет строки той же функцией, что и вердикт (`evaluate.judged_rows`), и
сверяет итог с записанным в прогоне (`total_return_net`). Не сошлось — график рисуется, но
с пометкой «код стратегии с тех пор менялся»; нет записанного итога (старый прогон) — сверки
нет, пометки тоже.

## Где что

- `qlab.forward_series` — ряд, хранение, пересчёт, сборка того, что рисует консоль;
- `GET /api/ideas/{id}/forward` — по этапу: `series` или `message` (ряда ещё нет);
- `web/src/components/ForwardCharts.jsx` — график и подписи;
- утренний отчёт: раздел «Графики прошедших идей» — по строке на идею, прошедшую за ночь, со
  ссылкой на страницу в консоли (markdown графиков не рисует) и пометкой, готов ли ряд.
