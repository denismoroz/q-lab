# Руководитель исследований (2026-10-25, задача T56)

Владелец, 2026-10-25: «я думаю в агентах не хватает агента эксперта - который бы следил за
направлениями поиска и корректировал действия генератора идей исследователя»; про расписание:
«запуск руководителя раз в 2 дня - добавляй».

## Зачем

Ищут стратегии два агента: **генератор идей** берёт механизмы из каталога `docs/MECHANISMS.md` и
пишет описания новых стратегий, **исследователь** улучшает четыре названные стратегии (Bv2, trend,
FRAB, XSMOM). Каждый видит только свой кусок. Никто не смотрит на поиск целиком: какие
направления раз за разом упираются в один и тот же отказ, где тратятся токены, а где ничего не
выходит, чего не хватает каталогу и данным. Это работа руководителя. Он советует, код проверяет
каждое его слово и применяет только проверенное.

**Руководитель задаёт направления, а не значения параметров.** Он не выбирает окно, порог, список
монет или таймфрейм ни для одной стратегии. Поэтому в его файле доказательств нет ни доходности,
ни Шарпа, ни просадки отдельных вариантов: иначе направления подгонялись бы под данные проверки
вперёд, и проверка перестала бы быть проверкой вперёд.

## Что руководитель видит

Файл доказательств строит код (`qlab.agents.director.build_evidence`), записывается в
`data/research/director-<дата>.md`. Посмотреть без трат токенов:

    uv run qlab director --dry-run

В файле:

1. **Воронка** — за последние 14 дней и с 2026-10-03: сколько идей придумали агенты, сколько
   прогнано на стенде, куда стенд их направил, сколько выживших, сколько токенов и какова цена
   одного выжившего (`src/qlab/funnel.py`). Токены исследователя — ещё и по стратегиям, из
   сохранённых состояний ночей.
2. **Исходы по направлениям.** Каждая идея, созданная агентом, попадает в направление: идеи
   генератора — по **семейству механизма** (из заголовка `# mechanism:` в его спеке, а если спека
   нет — из пометки идеи), опыты исследователя — по их стратегии. По каждому направлению:
   сколько идей, сколько ни разу не прогонялось, их статусы сегодня, куда направил последний
   прогон каждой, **какие правила он не прошёл** (названия правил, без значений). Никаких метрик. Провалы правил про нашу инфраструктуру (`venue_supported`: у нас нет кода, ставящего ордера на площадке данных) считаются отдельной строкой: это факт о нашей установке, а не об идее, и причиной закрыть направление он быть не может.
3. **Покрытие каталога** — по семействам: сколько механизмов собирается из блоков целиком (так
   говорит таблица «Каких параметров не хватает» в самом каталоге), чего каждому не хватает, что
   блоки не выражают, сколько идей по нему уже сделано.
4. **Предложения исследователя вывести варианты** (строки `DROP:` из его последней записки — числа
   в причинах заменены на `#`, потому что причина могла цитировать, как вариант себя показал) и
   **идеи владельца** для исследователя дословно.
5. **Детектор затухания** — последние строки по работающим книгам (то, что показывает владельцу
   `src/qlab/decay.py`).
6. **Прежние направления** руководителя и их статус.

## Что руководитель пишет

Записку для владельца (`docs/research/director-<дата>.md`, по-русски, простыми словами) и в конце
один блок. Код принимает только это:

| раздел блока | что значит | что с ним делает код |
|---|---|---|
| `generator.prefer_mechanisms` | механизмы, которые генератору стоит брать первыми | называются в инструкции генератора; совет, не приказ |
| `generator.pause_mechanisms` (`id`, `why`) | механизмы на паузе | спек такого механизма **отвергает охрана генератора**, прогон не начинается |
| `researcher.<стратегия>.priority` | `high`, `normal`, `low` | ночью стратегии идут по важности: сначала `high`; при нехватке бюджета отрезается `low` |
| `researcher.<стратегия>.note` | пометка простым текстом | дописывается к вопросу исследователю; **пометка с цифрой отбрасывается** (цифра — это значение параметра) |
| `catalogue_requests` (`family`, `look_for`, `why`) | задания будущему агенту каталога | записываются; пока никто не исполняет |
| `data_requests` (`what`, `why`) | какие данные нужны | записываются; пока никто не исполняет |
| `propose_close_family` (`family`, `why`) | предложение закрыть направление | **код его не применяет**; в отчёте помечено «решает владелец» |

Код отвергает: идентификаторы механизмов, которых нет в каталоге; стратегии, которых нет в
`night/research.yaml`; паузу без причины; предложение закрыть неизвестное семейство. Механизм
не может быть одновременно предпочтительным и на паузе (пауза сильнее). Всё отброшенное
перечислено в разделе «Что принял код» в конце записки и в утреннем отчёте. Блок, который не
разобрался как YAML, не меняет ничего: прежний файл остаётся.

Руководитель работает на модели opus через бюджетный гард (`CLAUDE.md`): вызов без бюджета падает.
Читать он может всё, писать — только свою записку; файл `night/directions.yaml` принадлежит коду, и
если агент его тронул, код возвращает прежнее содержимое. Чужие файлы, которые изменились за время
вызова, код **не откатывает** (урок 25 октября: охранник не отличает чужую работу от нарушения) —
он называет их в отчёте.

## Проверка владельца перед тем, как код действует

Самые первые направления в истории записываются с пометкой `pending_owner_review: true`. Пока она
стоит, генератор и исследователь ведут себя так, как будто файла нет — как до руководителя.
Следующий запуск, пока файл так и не проверен, тоже пишет пометку (проверять нечего, кроме
накопленного). Когда владелец прочитал записку и согласен:

    uv run qlab director --approve

или вручную `pending_owner_review: false` в `night/directions.yaml`. С этого момента направления
действуют сразу, без второй проверки (так договорено: проверка нужна один раз, на первом).
Чтобы вернуть проверку, достаточно поставить пометку обратно.

Файла нет, он повреждён или ждёт проверки — поведение прежнее: ничего не управляется.
История: `data/directions/<дата>.yaml` — что руководитель писал каждый раз.

## Ночью

`night/director.yaml`: `enabled: true`, `cadence_days: 2`, семейства механизмов и слова владельца.

- Идёт **раз в два дня**, **до исследователя и генератора** в те ночи, когда запускается, в
  бюджете стадии «реализация» (она кормит самую дорогую работу, которой руководитель управляет).
  Из доли этой стадии он берёт одну из `1 + число стратегий исследователя`, а не всё.
- Не хватает бюджета — **пропуск**, не сбой: в отчёте строка «не запускался», перепроверка не
  страдает (она идёт раньше и токенов этой стадии не берёт). Остановленный запуск продолжается
  следующей ночью, а не ждёт ещё два дня.
- Состояние ночи хранит метки `director:agent` (вызов агента закончен, токены потрачены) и
  `director:directions` (блок проверен и записан, токенов не нужно). Прерванная после вызова ночь
  не платит второй раз: записка разбирается заново.
- Ночь без исследователя (`--no-research`) руководителя не запускает; принудительно, в обход
  расписания и `enabled` — `qlab night run --director`, отключить — `--no-director`.
- Утренний отчёт, раздел «Руководитель исследований»: записка, что поручено генератору и
  исследователю, просьбы к каталогу и о данных, **предложения закрыть направление — «решает
  владелец»**, пометка о проверке и список отброшенного кодом.

Порядок стратегий исследователя при включённых направлениях: сначала по важности, внутри одной
важности — те, что остановил бюджет прошлой ночью, потом по имени. Стратегия с `low` может
остаться без ночи, если бюджета не хватает; руководитель пересматривает важность раз в два дня.

## Запуск вручную

    uv run qlab director --dry-run     # файл доказательств, токенов не тратит
    uv run qlab director               # вызов агента через бюджет, затем запись направлений
    uv run qlab director --no-apply    # только записка, блок не разбирать
    uv run qlab director --approve     # владелец проверил: направления действуют

## Честные ограничения

- Запрет искать результаты отдельных вариантов (записки исследователя, отчёты ночей, спеки)
  держится на инструкции. Код не может проверить, что агент туда не заглянул, как и в случае с
  датой отреза у исследователя; записка должна сказать, на что он опирался.
- Цифру в пометке код ловит, число словами («четыре») — нет.
- Семейства механизмов — это не поле каталога, а группировка в `night/director.yaml`
  (импульс, возврат цены, низкий разброс, фандинг и базис). Её составил автор задачи; владелец
  может перегруппировать. Механизм вне групп считается своим семейством.
- Просьбы к каталогу и о данных пока только записываются.
- Токены генератора по семействам не разделить (реестр знает только агента), поэтому по
  направлениям расходы показаны по агентам и, для исследователя, по стратегиям.
