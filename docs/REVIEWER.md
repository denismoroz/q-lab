# Агент-проверяющий (2026-10-02)

Третий пункт защиты звена «карточка → код» (этап 5, `docs/PLAN.md`). Автоматические
проверки ловят подглядывание в будущее (`docs/LOOKAHEAD.md`) и число ниоткуда
(`docs/SOURCES.md`). Не ловят они главное: механизм, который описан в источнике, но молча
не выражен в коде. Так фреймворк однажды отверг работающий FRAB — у копии не было его
двухфазного безубытка.

## Как устроено

- Роль в плане — Adversary, модель opus: «поиск look-ahead и дыр — единственное место, где
  нужен сильный судья».
- На вход: **источник** (карточка, цитаты статьи или код frab, который копия должна
  повторить), **спек** и **код** q-lab с номерами строк. Всё в одном задании, своя
  системная подсказка, никаких инструментов: агент не бродит и не платит 40 тысяч токенов
  за подсказку Claude Code.
- Вызов идёт только через бюджетный гард (`docs/BUDGET.md`), стадия «реализация».

**Модель предлагает, код решает** (CLAUDE.md). Каждая находка обязана нести
доказательства, которые проверяет код:

- дословная цитата из источника (с точностью до пробелов);
- место в коде — файл и строки, которые существуют.

Находка, чьи доказательства не сошлись, отбрасывается с причиной. Принятые хранятся в
таблице `review` — для именно этой реализации (поля стратегии в спеке и текст кода):
изменился код — нужен новый просмотр.

**Что решает код.** Пока в последнем просмотре этой реализации есть принятая находка
вида «механизм не выражен», «параметр не совпадает с источником» или «возможное
подглядывание», а спек её не объявил в `unexpressed_mechanisms` и не ответил в
`review_answers`, прогон — «не оценима» с названной находкой.

Команда: `qlab review SPEC --source ФАЙЛ [--source ФАЙЛ ...] [--blind]`. С `--blind`
агенту не показывают объявленный в спеке список невыраженных механизмов — так проверяется
сам проверяющий.

## Проверка проверяющего: старая копия Bv2 вслепую

`specs/bv2.yaml` (копия Bv2, не живой код) против кода frab (`b2/book.py`, `b2/params.py`),
список невыраженных механизмов скрыт. Ответ известен заранее: в спеке объявлены два —
модель маржи с ликвидацией и доливкой и докупка спота после закрытия страховки.

Найдено 6, отброшено 0, потрачено 42 766 токенов:

| вид | что нашёл | известно заранее? |
|---|---|---|
| механизм не выражен | модель маржи: частичная страховка по свободной марже, доливка продажей спота, ликвидация по максимуму бара | **да** |
| механизм не выражен | докупка спота до цели, когда тренд снова вверх | **да** |
| параметр не совпадает | размер спота: при включённой марже frab считает его по формуле от плеча (BTC ≈0.45, SOL/AVAX ≈0.36 капитала монеты), копия — половина капитала | новое (часть модели маржи) |
| механизм не выражен | «carry» на свободном резерве | новое; на проде carry выключен, поэтому в копии его нет сознательно — ответ для `review_answers` |
| другое | frab решает на баре i по сигналу бара i−1, копия — по сигналу того же бара | **новое** |
| другое | «12 часов подряд без сигнала» на дневных барах вырождается: копия может снять страховку на первом же дне | **новое** |

Обе известные дыры найдены вслепую. Две новые находки — настоящие расхождения старой
копии с frab, которых никто не замечал; живой переходник (`specs/bv2-live.yaml`) их не
имеет, потому что вызывает сам код frab.

## Чего проверяющий не гарантирует

- Он может пропустить механизм: это сито, как и остальные проверки. Один просмотр с
  известным ответом — ещё не доля пропусков; её стоит мерить так же, как ложные отказы
  (T26), на наборе реализаций с известными дырами.
- Находка «другое» не блокирует прогон: такие расхождения разбирает человек.
