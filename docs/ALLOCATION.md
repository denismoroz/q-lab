# Распределение капитала между стратегиями (T55, часть 2)

Вторая половина этапа 7 (`docs/PLAN.md`, M6): первая половина — детектор затухания
(`docs/NIGHT.md`, `src/qlab/decay.py`). Здесь отвечаем на вопрос: **как поделить деньги
владельца между стратегиями пула и когда делить заново.**

**Код предлагает, решает владелец.** Раздел «Распределение капитала» утреннего отчёта и
`GET /api/allocation` — это расчёт. Он не переводит деньги, не меняет статусы, не пишет на прод и
не вызывает агентов. Страницы в консоли пока нет — только интерфейс данных.

## Метод и почему он

**Доля стратегии обратно пропорциональна её дневному разбросу.** Дневной разброс — насколько день
в среднем отличается от обычного дня (стандартное отклонение дневной доходности). Спокойным
стратегиям достаётся больше денег, беспокойным меньше, так что каждая вносит в общую качку
примерно поровну. Это самый простой «паритет риска».

Почему не что-то сложнее. Пул — несколько стратегий (лимит 6) с историей в недели. Чем больше
чисел оценивается по такому ряду, тем больше в них ошибки:

- DeMiguel, Garlappi, Uppal (2009), *Review of Financial Studies* 22(5), 1915–1953: ни одна из
  14 оптимизирующих моделей устойчиво не обыграла простое деление поровну, потому что ошибка
  оценки съедает выигрыш; чтобы оптимизация победила, нужны окна порядка 3000 месяцев на 25
  активов. У метода есть критики (Kritzman, Page, Turkington, 2010), поэтому берём метод, которому
  нужно одно число на стратегию.
- Asness, Frazzini, Pedersen (2012), *Financial Analysts Journal* 68(1), 47–59: «простой паритет
  риска» — вес каждого актива равен единице, делённой на его разброс; конструкция не требует
  оценок ковариаций (текст статьи прочитан 2026-10-25). Их окно — три года помесячно; у нас недели,
  поэтому окно не выбирается: берутся все дни, что есть у стратегии.
- Maillard, Roncalli, Teiletche (2010), *Journal of Portfolio Management* 36(4), 60–70: при
  одинаковых парных корреляциях «равный вклад в риск» совпадает с весами 1/разброс. Свойство
  проверяет тест. Слова владельца в `docs/PLAN.md` (M6) — «risk-parity по драйверам» — взяты в
  самом дешёвом виде.

**Ожидаемая доходность в расчёт не входит**: за недели её не отличить от случайности (запись
заранее от 21.09, ПРЕДСКАЗАНИЕ 0). **Корреляции не оцениваются для долей**, но показываются: на
общем окне пары, не меньше 28 дней.

Метод, параметры, источники и обоснование — `night/allocation.yaml` (версия 2026-10-25.1).
Записано заранее, до любого расчёта на настоящих данных:
`seed/preregistration/2026-10-25-capital-allocation.yaml`.

## Откуда числа

| что | откуда |
|---|---|
| ряд доходности стратегии | выгрузка ночи (`data/paper/<день>/`), только настоящий отрезок (с `realised_from`), на `strategy_capital_usd` книги — **никогда на деньгах счёта** (правило владельца 2026-10-25); для живой книги — только `equity_from: strategy_pnl` |
| стратегия без книги | прогон на стенде с `params_fixed_at` и позже; если у спека такой даты нет — это период подбора, веса нет |
| «одна стратегия» | корень цепочки родителей в реестре: три книги Bv2 — одна стратегия, ряд берётся один (самый длинный; при равенстве — корневая идея); результаты не выбираются |
| минимум дней | 28 — «как минимум 4–6 недель» владельца, как в `qlab.paper_rule`; тест связывает два числа |
| минимальный капитал стратегии | `min_capital_usd` последнего испытания (минимальная нога площадки $10 делится на наименьший вес) |
| лимит стратегий | `night/limits.yaml`, 6 |
| общая сумма | $3000 — **рабочее допущение**, то, на чём считает ночь; владелец такую сумму не называл (его цифры: «не более 1к», $5–15 тысяч, горизонт 100–120 тысяч). Отчёт показывает деление и при 1000, 5000, 15000 |

## Что делает код с ограничениями

- Доли меньше минимума стратегии быть не может: стратегия с наименьшим отношением «досталось /
  минимум» получает ноль, остальные делятся заново; в отчёте — сколько ей досталось бы, какой нужен
  минимум и **при какой общей сумме она войдёт**.
- Данных меньше 28 дней: живая стратегия остаётся с теми деньгами, что есть (настоящие деньги не
  двигаем на неделях данных), остальное делится; бумага и стенд получают ноль и дату, когда
  данных хватит.
- Только период подбора — ноль, с этой причиной.
- Кандидатов больше лимита — расчёта нет, выбор за владельцем.

## Поводы пересчитать деление (без новых порогов)

Набрались 28 дней данных · стратегия прошла правило бумаги (4–6 недель, повтор сошёлся) · в пуле
появилась новая стратегия или ушла старая · детектор затухания отметил стратегию (пока порог
`alert_percentile` не задан — только показ; `on_decay_alert: exclude` исключает отмеченную и делит
заново — включает владелец). Дрейф долей сам по себе поводом не считается. Отчёт сравнивает с
прошлой ночью (состояние ночи хранит снимок).

## Что решает владелец

1. Общая сумма: 1000 / 3000 / 5000 / 15000.
2. Потолок на каждую стратегию. Его нет в расчёте; сделано допущение, что доходность на доллар не
   зависит от размера. Измерение ёмкости есть только для trend (`docs/T27_LIQUIDITY.md`).
3. Порог тревоги детектора и что делать по нему: показывать или исключать.
4. Как часто пересчитывать: по поводам (так сейчас), по календарю или при сдвиге доли на число
   пунктов — число называет владелец.
5. Лимит стратегий, если кандидатов больше шести.

## Проверка метода

Предсказание из записи: у каждой стратегии с долей дневной разброс за следующие 28 дней, делённый
на разброс, из которого считалась доля, лежит в границах, которые допускает один шум выборки
(формула в записи). Проверяется отдельным файлом результата, как в `2026-10-02-outcome-*.yaml`.

## Запуск и тесты

    uv run qlab pool-allocation --paper-root data/paper --night-dir data/night
    uv run pytest src/qlab/test_pool_allocation.py

Ночь считает раздел сама после детектора затухания (`qlab.night`), сохраняет его в состоянии ночи
(`allocation`) и пишет в отчёт.

## Расчёт на 2026-10-25 (выгрузка `data/paper/2026-10-25`)

Из трёх стратегий пула делится одна. **Bv2** (бумага, 41 день, дневной разброс 0.67%) получает
$2910 из $3000. **Тренд** (бумага, 40 дней) по формуле получил бы $1134, а его минимум по стенду —
$2442: ноль; войдёт при общей сумме от $6357 (при $15 000 — $5810). **FRAB** (настоящие деньги,
15 дней из 28) остаётся с $90; 28 дней у него будет 06.11, и тогда его малый разброс отдаст ему по
формуле почти всё, если потолка нет — это вопрос 2. Ряд тренда — книга `trend-live` (остановлена
владельцем 25.10, но её история настоящая); книга с выбором монет кодом идёт с 25.10 и станет
рядом, когда наберёт 28 дней.
