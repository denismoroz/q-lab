# q-lab — план

## Зачем

Ответить на вопрос, который нельзя решить ощущением: **сколько стоит найти замену
стратегии, переставшей работать, и растёт ли эта цена.** Отсюда всё остальное —
реестр, стенд, скамейка, аллокатор.

Не «конвейер поиска стратегий», а три механизма:

| механизм | отвечает на |
|---|---|
| счётчик выхода (воронка) | где потолок |
| детектор затухания | когда нужна замена |
| скамейка + аллокатор | чем менять |

Поиск — поставщик скамейки, а не цель.

## Границы

- q-lab **не ставит ордеров никогда.** Research → спек + досье + воспроизводимый
  прогон. Paper/live — на `10.8.0.5` через расширение frab.
- Разработка и отладка всей цепочки — на Mac.
- Данные — только бесплатные. К платным вернуться, если упрёмся в потолок.
- Капитал книги: $5–15k. Цель — пул 5–7 работающих стратегий с заменой.

## Четыре источника кандидатов

Дно у каждого своё, поэтому воронка режется по источнику:

1. **публикации** — конечный ресурс, почти выбран вручную;
2. **кладбище на новых данных** — пополняется само, со временем;
3. **ёмкость работающего эджа** — новые площадки под известную стратегию;
4. **изменения структуры рынка** — запуски площадок, новые инструменты, смена
   механик funding и комиссий. Единственный источник, который не иссякает.

## Milestones

### M1 — реестр, кладбище, воронка ← **сейчас**
Схема из `docs/REGISTRY.md`, движок правил, импорт существующего кладбища из
funding-rate-arbitrage, три запроса, CLI.

*Приёмка:* на реальном кладбище получены три списка — убитые отменёнными правилами,
почти прошедшие, дозревшие для перепроверки.

### M1.5 — калибровка самого набора правил ← **добавлено 2026-09-20**

Владелец не обязан доверять критериям на слово. У каждой версии правил измеряются
две собственные ошибки, и они хранятся вместе с версией:

- **доля ложных допусков** — сколько синтетических стратегий с заведомо нулевым эджем
  набор правил пропускает (перемешанные знаки сигнала, случайные веса, bootstrap с
  разрушенной предсказательной связью на реальных данных);
- **доля ложных отказов** — отвергает ли набор правил то, что заведомо работает:
  FRAB, Bv2, Trend.

Повод — история XSMOM. Он был отобран по единственному критерию «некоррелированность
с FRAB», развёрнут на деньги и оказался никогда не прибыльным. Ошибка была не в мягких
порогах, а в том, что критерий оптимизировал не тот показатель: **некоррелированность —
это то, как выглядит шум**, поэтому отбор по декорреляции систематически поднимает
наверх неработающее и одновременно хоронит рабочее за «похожесть на уже работающее»
(так на кладбище оказались Bv2 и Trend).

Отсюда постоянное правило: **ни одно правило не может стать допускающим критерием,
пока не измерено, как часто через него проходит шум.** Это обобщение `harness_power`
из frab, где так калибровали PBO и DSR по отдельности, на весь набор целиком.

*Приёмка:* набор `2026-09-20.1` имеет измеренные обе доли; отбор пропускает FRAB, Bv2
и Trend и заворачивает шум.

### M2 — слой данных и стенд
Снапшоты в parquet с хешами, перенос `xsec` и `harness_power` из frab в
`qlab.harness`, журнал испытаний.

*Приёмка:* известный результат из frab воспроизводится через новый стенд с тем же числом.

### M3 — здоровье живых стратегий
Карточки драйверов, мониторы драйверов (не PnL), CUSUM как вторичный сигнал.

*Приёмка:* три живые стратегии frab имеют наблюдаемый драйвер и порог тревоги.

### M4 — preflight, скамейка, перевалидация
Гейт исполнимости под капитал до расчётов; жизненный цикл `bench`; ночная
перевалидация скамейки и дозревшего кладбища.

### M5 — аллокатор
Risk-parity по драйверам, ёмкость как ограничение, явный порог замены
(> ошибка оценки + издержки переключения), дефляция перед сравнением.

### M6 — агенты и ночной прогон
Scout (публикации), Venue-watcher (структура рынка), Formalizer, Implementer,
Adversary, Archivist. Ночной цикл с бюджетом токенов.

### M7 — UI
Четыре экрана: воронка · реестр и кладбище · скамейка и капитал · ночной прогон.
Появляется раньше, кусками, как только в реестре есть что показывать.

## Модели для агентов системы

| роль | модель | почему |
|---|---|---|
| Scout, Venue-watcher | sonnet | объём и дешевизна, выход проверяется кодом |
| Formalizer | sonnet | формализация по шаблону |
| Implementer | sonnet | код против фиксированного API + тесты |
| Archivist | sonnet | генерация досье из данных реестра |
| Adversary (red team) | opus | поиск look-ahead и дыр — единственное место, где нужен сильный судья |

Вердикты по стадиям выносит **код**, не модель — на любой модели.

## Разработка

Реализация — sonnet-субагенты по задачам из `docs/TASKS.md`, ревью — opus.
