# q-lab — план

## Зачем

Ответить на вопрос, который нельзя решить ощущением: **сколько стоит найти замену
стратегии, переставшей работать, и растёт ли эта цена.** Отсюда всё остальное —
реестр, стенд, скамейка, аллокатор.

Не «конвейер поиска стратегий», а три механизма:

| механизм | отвечает на |
|---|---|
| счётчик выхода (воронка) | где потолок |
| детектор затухания | когда нужна замена |
| скамейка + аллокатор | чем менять |

Поиск — поставщик скамейки, а не цель.

## Границы

- q-lab **не ставит ордеров никогда.** Research → спек + досье + воспроизводимый
  прогон. Paper/live — на `10.8.0.5` через расширение frab.
- Разработка и отладка всей цепочки — на Mac.
- Данные — только бесплатные. К платным вернуться, если упрёмся в потолок.
- Капитал книги: $5–15k. Цель — пул 5–7 работающих стратегий с заменой.

## Четыре источника кандидатов

Дно у каждого своё, поэтому воронка режется по источнику:

1. **публикации** — конечный ресурс, почти выбран вручную;
2. **кладбище на новых данных** — пополняется само, со временем;
3. **ёмкость работающего эджа** — новые площадки под известную стратегию;
4. **изменения структуры рынка** — запуски площадок, новые инструменты, смена
   механик funding и комиссий. Единственный источник, который не иссякает.

## Что такое фреймворк

Одна точка входа. На входе — спек стратегии, на выходе — вердикт с числами:

```
qlab evaluate <spec>
  -> preflight: при каком МИНИМАЛЬНОМ капитале исполнима (число, не гейт)
  -> данные:    point-in-time универс, снапшот с хешем
  -> прогон:    позиции × цены × funding/borrow × реальные косты
  -> испытания: записан каждый прогон, дефляция по фактическому числу
  -> проверка:  отложенное окно, хвост, драйвер
  -> ВЕРДИКТ:   paper / live / полка (нужно $X) / reject / нужно больше данных
```

Всё остальное в проекте — способы поставлять спеки на этот вход (поиск, кладбище,
наблюдение за площадками) либо способы следить за тем, что уже вышло с выхода
(мониторы драйверов, лестница капитала). Сам вердикт выносит код по версионируемым
правилам, на любой модели.

Конкретные стратегии — Bv2, Trend, FRAB — это **входы фреймворка, а не задачи**.
Вопрос «работают ли они» получает ответ как первый результат конвейера, а не как
отдельный ручной разбор: ручной разбор не масштабируется и ничего не доказывает
про метод.

## Milestones

### M1 — реестр, кладбище, воронка ✅
Схема, движок правил, импорт кладбища, три запроса, CLI. Приёмка пройдена 2026-09-20.

### M2 — ядро: от спека до вердикта ← **сейчас**
То, чего сегодня нет и без чего правила нечего оценивать.

- **слой данных** — снапшоты в parquet с хешами, point-in-time универс с умершими
  инструментами, источники HL и Binance;
- **минимальный капитал как метрика** — `min_capital_usd` считается для каждого
  кандидата из фактически принимаемых весов и минимального размера ноги площадки.
  Отбор отвергает только то, что выше всего горизонта капитала ($120k); остальное
  маршрутизируется числом: финансируемо сейчас или на полке до нужного уровня.
  Частично исполняемая стратегия — **другая стратегия с другим эджем**, поэтому
  урезанный вариант оформляется отдельным спеком, а не подразумевается;
- **интерфейс стратегии** — спек → целевые позиции во времени; одинаково описывает
  cross-sectional, trend, carry и спот+хедж;
- **стенд** — позиции × цены × funding/borrow × косты → метрики; accrual обязателен
  по конструкции, отказ — только явным `NO_ACCRUAL`;
- **журнал испытаний** — пишется каждый прогон, включая выброшенные;
- **`qlab evaluate`** — сквозная команда: спек → метрики → движок правил → вердикт.

*Приёмка:* известная стратегия из frab воспроизводится с тем же числом и получает
вердикт автоматически.

### M3 — калибровка набора правил
Две собственные ошибки каждой версии правил: доля ложных допусков на синтетическом
шуме и доля ложных отказов на заведомо рабочих. Повод — XSMOM: отбор по
декорреляции систематически поднимает шум, потому что **некоррелированность — это
то, как выглядит шум**. Ни одно правило не становится допускающим критерием, пока
не измерено, как часто через него проходит шум.

### M4 — предварительная регистрация и сверка вперёд
Ожидание фиксируется до первого взгляда на результат (коммит как отметка времени),
дальше еженедельная сверка факта с ожиданием. Ступени: согласие драйвера и костов
сходятся за недели, распределение — за месяцы, PnL — за годы. Тот же прибор
работает в обе стороны: повышает бумажную стратегию и понижает затухающую.

### M5 — скамейка и перевалидация
Жизненный цикл `bench`, ночная перевалидация скамейки и дозревшего кладбища.

### M6 — аллокатор
Risk-parity по драйверам, ёмкость как ограничение, явный порог замены больше ошибки
оценки плюс издержек переключения.

### M7 — агенты и ночной прогон
Scout, Venue-watcher, Formalizer, Implementer, Adversary, Archivist. Поставщики
спеков на вход `qlab evaluate`.

### M8 — UI
Воронка · реестр и кладбище · скамейка и капитал · ночной прогон.

## Модели для агентов системы

| роль | модель | почему |
|---|---|---|
| Scout, Venue-watcher | sonnet | объём и дешевизна, выход проверяется кодом |
| Formalizer | sonnet | формализация по шаблону |
| Implementer | sonnet | код против фиксированного API + тесты |
| Archivist | sonnet | генерация досье из данных реестра |
| Adversary (red team) | opus | поиск look-ahead и дыр — единственное место, где нужен сильный судья |

Вердикты по стадиям выносит **код**, не модель — на любой модели.
