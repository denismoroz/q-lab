# Издержки: одна таблица на площадку (2026-10-29)

Владелец, 2026-10-29, на карту путей оценки (`docs/EVALUATION_PATHS.md`, вопрос В7: «одна таблица
на площадку, спек отступает только с источником»): «да, по всем рекомендациям, делай». Код —
`src/qlab/costs.py`, таблица — `night/costs.yaml`.

## Слова

**Издержки** — что стратегия платит за каждую сделку: **комиссия** биржи за заявку, которая берёт
чужую (на бирже это называют «taker»; мы говорим «комиссия») и **проскальзывание** — на сколько
цена сделки хуже цены, которую мы видели в расчёте. Обе величины в **базисных пунктах** (б.п.):
один б.п. — одна сотая процента, 4,5 б.п. = 0,045%. **Площадка** — биржа (Hyperliquid, Binance).
**Спек** — описание стратегии, одна страница, по которой стенд её считает.

## Зачем

Одну и ту же площадку разные спеки считали по-разному: Hyperliquid — то 3,5 б.п. (число из
репозитория `frab`; почему именно оно, там не записано, `docs/TWO_STAGE.md`, «Комиссия»), то 4,5 б.п.
(опубликованная таблица самой биржи, базовый уровень; так считает второй этап). У двухножевых книг
(Bv2, FRAB: монета и контракт на неё) были смеси из двух комиссий: 5,25, 7,25, 7,5. Две идеи на
одной площадке можно было сравнивать только после чтения обоих спеков.

код, что проверяет источники в спеках (`qlab.pipeline.sources`): файл есть, число в нём написано, формула
даёт ровно это число.

## Правило

Издержки спека — строка той площадки, **куда пойдут заявки** (`execution_venue`, иначе
`data.source`). Спек с другими числами обязан объяснить это в `sources["costs.differs_from_table"]`
ссылкой, которая называет что-то проверяемое (файл, адрес, дату решения владельца, формулу); без
этого спек не запускается (`qlab.costs.problems`, зовётся из `source_problems`). Объяснение,
когда числа равны таблице, — тоже ошибка: лишнее предложение прячет настоящие отличия.

Смесь из двух ног (монета и контракт) — всегда отличие: формула смеси и есть источник.

**От сегодняшнего дня таблица — умолчание:**

- второй этап (`night/stage2.yaml`) больше не хранит чисел издержек, а читает строку площадки
  (раньше те же 4,5 + 0,9 стояли в `stage2.yaml`; числа не изменились);
- генератор идей: издержки спека обязаны совпасть со строкой `binance`, у агента нет права писать
  `costs.differs_from_table`; агент-реализатор карточек берёт строку `hyperliquid`
  (`src/qlab/agents/generator.py`, `implementer.py`).

Спеки, написанные раньше, числа сохранили: смена издержек у открытой идеи — смена стенда, которую
пересчёт пересчитал бы заново, и решает её владелец. Каждый такой спек получил то самое
предложение `costs.differs_from_table` со ссылкой, которая у него уже была (в 142 из 164 файлов
`specs/`, числа не тронуты: тест сверяет, что в файле не изменилось ничего, кроме этой строки).

**С 2026-10-30 прогон на данных Binance судится для Binance** (`docs/VENUE_SPLIT.md`): в спеке нет
`execution_venue`, поэтому издержки — строка `binance` (5,0 + 0,9; для книги с ногой на споте 7,5 + 0,9), а не
Hyperliquid, как было, пока Binance был подменой данных для Hyperliquid. Десять открытых спеков на
истории Binance переписаны (в тестах: `test_the_open_binance_specs_are_judged_for_binance_with_binances_numbers`),
предложение `costs.differs_from_table` у них снято. Второй этап (Hyperliquid) берёт строку
`hyperliquid`, как и раньше.

решение стенда, которое пересчёт перемерит; в этот раз не принято.

## Что здесь ещё не решено

- Вопрос, почему `frab` берёт 3,5 б.п., а не 4,5 б.п. опубликованной таблицы: в его репозитории не
  записано. Пока этого нет, 3,5 остаётся «числом `frab`» в спеках с ссылкой на источник.
- Комиссию Binance по живой таблице прочитать не удалось: страницу собирает скрипт.
- Скидки по объёму и по оплате комиссии монетой биржи не применяются (деньги стратегий малы).
