# Страница идеи начинается с простых слов (2026-11-03)

Владелец, 2026-11-03: «я открываю карту стратегии http://localhost:5890/ideas/bv2-research-shared-pool-hl-causal
смотрю и не могу понять - а что она вообще делает и как - туча цифр слов - а что она делает - не понятно -
можно это как-то починить для всех стратегий?»

Раньше простое описание («Как работает стратегия») показывалось только у идей с карточкой в `cards/`.
У вариантов, двойников, вторых этапов (`-hl`), надстроек, опытов исследователя и идей генератора была
длинная техническая строка и числа.

## Что видно на странице

Страница каждой идеи открывается пятью вещами; лестница, числа и графики идут ниже, как раньше.

1. **Короткое название** (до 80 знаков) крупно, под ним мелко прежнее длинное техническое.
2. **Что делает стратегия** — 3–6 коротких предложений простыми словами: что держит, что покупает и
   продаёт и когда, почему должна зарабатывать, чем рискует, на каких деньгах работает.
3. **Чем этот вариант отличается** — список отличий от основной версии. Его считает код, руками он
   не пишется.
4. **Как выбраны числа** — один из трёх случаев (ниже).
5. **Где проверена** — площадка, с какой даты история, и что значит «две проверки».

## Откуда берётся текст «Что делает стратегия»

Код идёт по цепочке и берёт первое, что нашёл (`src/qlab/plain/page.py`, `resolve`):

| шаг | откуда | когда |
|---|---|---|
| 1 | поле `plain_summary` в самом спеке | новый механизм или новое семейство (пишет исследователь или генератор) |
| 2 | карточка этой идеи (`cards/<идея>.yaml`, `plain_summary`) | у идеи есть карточка |
| 3 | текст семейства стратегий (`strategies/plain/<семейство>.yaml`) | семейство выбирается по стратегии, от которой идея произошла (корень цепочки `parent_id`), а затем по коду, который запускает спек |
| 4 | карточка ближайшего предка | у предка есть карточка, а текста семейства нет |
| 5 | механизм каталога (`strategies/plain/mechanisms/<id>.yaml`) | спек генератора с заголовком `# mechanism: <id>`; к нему код добавляет предложения, собранные из блоков спека |
| 6 | собственные слова `own_mechanism` спека | свой механизм генератора |
| 7 | «простого описания пока нет» | идея старого списка без спека и карточки; ниже цитата из реестра, что утверждал источник |

Ни одно предложение не пишет модель на лету: это либо файл, который написал и проверил человек,
либо фраза, которую код собирает из спека.

## Где лежат тексты

Всё — данные в `strategies/plain/`, код их только читает.

- `bv2.yaml`, `trend.yaml`, `frab.yaml`, `frab-binance-spot.yaml`, `frab-all-binance.yaml`, `xsmom.yaml`,
  `xyz-bab.yaml`, `noise.yaml` — по файлу на **семейство стратегий**;
- `mechanisms/<id>.yaml` — по файлу на **механизм каталога** (`docs/MECHANISMS.md`), сейчас 19;
- `params.yaml` — **словарь параметров**: что значит каждый параметр спека;
- `blocks.yaml` — фразы для блоков составной стратегии (`docs/BLOCKS.md`);
- `layers.yaml` — фразы для обёрток (перенастройка кодом, состояние рынка, надстройки).

В файле семейства:

```yaml
id: bv2
title: "Bv2: монеты со страховкой от падения"      # короткое название, до 80 знаков
roots: [strategy-b-v2]                              # стратегии, от которых идеи этого семейства происходят
code_refs: [qlab.strategies.live.bv2:LiveBv2, ...]  # или код, который запускают их спеки
base_specs: {LiveBv2: specs/bv2-live.yaml}          # основная версия: с ней код сравнивает вариант
base_name: "как на проде"                           # как называют основную версию
checked_against: [...]                              # по каким файлам проверено каждое предложение
facts_default: {short_window: 14, ...}              # числа, если спек их не называет
sentences: [...]                                    # 3–5 предложений, числа в {фигурных скобках}
```

Числа вариантов подставляет код: `{coins}`, `{short_window}`, `{lookbacks}`, `{capital}` и так далее
берутся из спека (список подстановок — `FACTS` в `src/qlab/plain/compose.py`). Предложение, для
которого спек числа не даёт, **выбрасывается целиком**, наполовину заполненных предложений нет. Сумма
денег стратегии всегда последним предложением: `strategy_capital_usd` спека, а если его нет — сумма,
на которой построена сама стратегия (`capital_usd`, `budget_cap_usdc`); остаток на счёте биржи в
расчёт не входит (`docs/CAPITAL_BASE.md`).

### Как добавить семейство

1. Прочитайте код стратегии и документы по ней. Каждое предложение — факт о том, что делает код.
2. Создайте `strategies/plain/<семейство>.yaml` по образцу выше. В `checked_against` назовите файлы,
   по которым проверяли каждое предложение (тест проверяет, что файлы из этого репозитория существуют).
3. Если нужна новая подстановка — добавьте функцию в `FACTS` (`src/qlab/plain/compose.py`).
4. Добавьте в `params.yaml` параметры, которых там ещё нет (тест назовёт каждый такой параметр).
5. `uv run pytest -q src/qlab/plain`: тест проверяет длину названия, число предложений и тот же
   список жаргона, что и карточки (`cards/SCHEMA.md`, «Правила заполнения»).

### Когда в каталоге появляется новый механизм

Тест `test_every_mechanism_of_the_catalogue_has_a_plain_text` краснеет, пока рядом с механизмом
в `docs/MECHANISMS.md` нет `strategies/plain/mechanisms/<id>.yaml`. Идея такого механизма и без файла
получает описание из своих блоков, но объяснение «почему должно зарабатывать» берётся только из файла.

## Как считается «Чем этот вариант отличается»

Код сравнивает спек идеи со спеком основной версии семейства (`base_specs`):

1. **Параметры стратегии.** Сначала с обёрток снимаются слои (`Retune`, `Overlaid`, `RegimeGate`,
   `SplitCadence`, `src/qlab/plain/specs.py`), сравниваются параметры самой стратегии. Каждое
   отличие — фраза из словаря: для «да/нет» целая фраза (`shared_margin: true` → «залог один общий на
   все монеты, а не у каждой свой»), для числа «<что это>: было A, стало B» (`hedge_margin_headroom`
   → «запас залога под страховку: было 1, стало 1.5»).
2. **Параметр, которого нет в словаре,** всё равно показывается: «параметр X: было A, стало B».
   Тест `test_every_parameter_of_the_specs_has_a_phrase_in_the_dictionary` называет каждый такой
   параметр из `specs/`, чтобы его добавили в `params.yaml` в тот же день.
3. **Параметр, добавленный в код позже остальных** (`shared_margin`, `short_window_days`, ...), имеет
   в словаре `default`: спек, где его нет, равен спеку, где он стоит на значении по умолчанию.
4. **Варианты, между которыми выбирает код** (сетка `grid` обёртки `Retune` или `choice` спека): если
   вариант — это один набор чисел против основной версии (опыт исследователя), этот набор и есть
   отличие идеи.
5. **Слои.** Надстройки («набирает позицию частями», «не торгует в части состояний рынка»), допуск
   по состоянию рынка, частота входа и выхода.
6. **Данные и издержки.** Площадка, свечи, список монет, наименьший оборот, комиссия и проскальзывание,
   наименьшая заявка.

Короткое название идеи — название семейства плюс самые короткие метки отличий («общий залог»,
«запас залога 1.5»), у второго этапа — «(проверка на Hyperliquid)».

## Как выбраны числа — три случая

(`src/qlab/plain/choice.py`)

- **Выбирает код.** Идея объявила значения, между которыми код выбирает каждый месяц только по прошлому
  (`Retune` с сеткой или `choice` спека, `docs/ONE_CHECK.md`, `docs/RETUNE.md`). Страница называет
  варианты словами: «как на проде» против «общий залог» — с пояснением, что каждый значит. Для
  старого вида (число оставлено открытым списком прямо в параметрах, `docs/OWN_NUMBERS.md`) — текст
  про выбор один раз на дату отреза.
- **Выбраны вручную.** Дата `params_fixed_at` и основание — первое предложение
  `params_fixed_evidence` как оно записано (если оно по-английски, страница так и говорит).
- **Выбирать не из чего.** `choice.nothing_to_choose` с причиной.

## Где проверена

(`src/qlab/plain/venue.py`) Площадка, с какой даты история и по какую, с какого дня идёт оценка
(`judged_from`), и одна строка про две проверки: Binance (история с 2019 года, торговать там нечем) и
Hyperliquid (с 2025 года, торговать можно); итог — лучший из двух (`docs/VENUE_SPLIT.md`). У идеи со
вторым этапом называется парная идея.

## Новые идеи: что обязаны дать исследователь и генератор

Вариант известной стратегии не пишет ничего: отличие считает код. Но спек **нового механизма или
нового семейства** описать некому, поэтому в нём должно быть поле `plain_summary` (3–6 коротких
предложений, без жаргона) и, по желанию, `plain_title` (до 80 знаков).

- Исследователь (`src/qlab/agents/researcher.py`): код проверяет каждый его спек; спек, чей код не
  относится ни к одному известному семейству, должен нести `plain_summary`.
- Генератор (`src/qlab/agents/generator.py`): спек механизма каталога ничего не добавляет (описание
  собирает код из блоков и числа спека), а спек `# mechanism: own` обязан нести `plain_summary` — иначе
  `check_generated` отклоняет его.
- Проверка одна и та же (`src/qlab/plain/check.py`): текст есть, не короче 120 знаков, русский, без слов
  из списка жаргона карточек (`qlab.agents.cataloguer.JARGON`).

## Чего эта страница не делает

- Не выносит вердикт и не меняет ни одного числа: она читает файлы и записанные строки.
- Не вызывает модель: токены не тратятся.
- Не подменяет карточку: карточка с источниками, защитой и тем, как умрёт, лежит по ссылке ниже.
- Не падает, если текст построить не удалось: тогда поле `plain` пустое, а страница открывается как раньше.
