# Двойники идей: проверка до прогона и по результатам

Решение владельца, 2026-11-04. 3 ноября семь вариантов Bv2 вывели как двойников: на истории
Binance пять из них дали одинаковые числа до последней цифры (+8,4% в год, падение −19,3%), потому
что код каждый месяц выбирал числа боевой версии. Ни одна проверка агентов этого не заметила.
Владелец: «может перед тем как создавать новую стратегию проверять на наличие уже такой - так мы
утонем в двойниках» → «да, делай».

Раньше генератор отказывал только в том же номере идеи и в тех же числах среди своих же
спеков; у исследователя проверки не было вовсе (только предел числа вариантов); карточник мог
написать «повтор» (суждение агента). Теперь двойников ловит код, в двух местах. Модуль —
`src/qlab/duplicates.py`. Агенты не вызываются, токены не тратятся, статусов код не меняет.

## 1. До прогона: отпечаток спека

Новая идея сравнивается с последним спеком каждой **открытой** идеи (не выведенной, не
отвергнутой, не распавшейся), которую стенд уже гонял. Идея, у которой ещё не было ни одного
прогона, в сравнении не участвует: иначе две одинаковые карточки отказали бы друг другу обе.

Отпечаток состоит из частей. Совпали все части — это дубль:

| часть | что в ней |
|---|---|
| код | код **внутренней** стратегии; обёртки `Retune`, `SplitCadence`, `RegimeGate`, `Overlaid` сняты |
| обёртки | то, что обёртка делает с весами (каденция входа и выхода, фильтр режима, надстройки); `Retune` сюда не входит, это «что выбирает код» |
| числа после умолчаний | числа стратегии с её собственными умолчаниями: число, записанное равным умолчанию, и пропущенное число — одно и то же |
| что выбирает код | списки значений идеи (`choice`) или сетка формы `Retune` — как набор полных вариантов (имена вариантов не считаются), и правило выбора |
| данные | площадка, площадка спота, как оценён спот, интервал, колонки спота, монеты и правило универса, минимальный оборот, первый день |
| издержки | комиссия, проскальзывание, минимальная нога |
| деньги стратегии | `strategy_capital_usd` |

В отпечаток **не** входят: номер идеи, название, комментарии, простые слова (`plain_*`), день
фиксации. Варианты, отличающиеся только этим, — двойники.

Умолчания берутся у самой стратегии (`DEFAULT_PARAMS` класса или единственный её класс `*Params` с
умолчаниями). Если умолчания узнать нельзя (модуль не импортируется), числа сравниваются как
написаны: код может пропустить двойника, но не придумать его.

### Где это включено

| вход новой идеи | что происходит с двойником |
|---|---|
| исследователь (`run_experiments`) | спек не запущен; в записке: «не запущен — дубль идеи X (…)» |
| генератор (`check_generated`) | спек отклонён с причиной «дубль идеи X (…)»; принятые в этом же заходе тоже сравниваются друг с другом |
| программист (`implement_run`, шаг проверки) | проверка не прогнана, остальные шаги карточки пропущены: «идея не запущена»; в отчёте «дубль идеи X» |
| надстройки (`overlay_stage`) | вариант не запущен, запомнен, чтобы не пробовать каждую ночь |
| `qlab evaluate` и `qlab implement --evaluate` | отказ с кодом выхода 1; запустить всё равно: `--allow-duplicate` (только у `evaluate`) |

Каждый отказ пишется в `data/duplicates/ledger.json` (раздел `refused`) и попадает в утренний отчёт.
Запущенная заново уже известная идея двойником не считается.

Агентам исследователя и генератора в файл с фактами добавляется список открытых идей простыми
словами и сказано, что двойники отклоняются кодом. Программисту список не нужен: он пишет код одной
карточки.

## 2. После прогона: одинаковые результаты

Прогон нового спека мог выглядеть иначе, но дать то же самое (пример 3 ноября). Поэтому после
прогона ряд дневной доходности **на деньгах стратегии** (`forward_series`, проверка вперёд)
сравнивается с последним прогоном каждой более старой открытой идеи **на той же площадке и том же
окне**:

- корреляция дневных доходностей не меньше 0,999;
- годовая доходность на общих днях различается не больше чем на 0,1 п.п.;
- общих дней не меньше 30 и не меньше 90% более короткого ряда; ряд без колебаний не сравнивается.

Совпало — идея получает пометку «дубль X по результатам» (раздел `results` того же файла). Это
**записанное показание**, само оно ничего не решает: статус не меняется, вердикт не меняется. Его
видно:

- на странице идеи — жёлтая полоса над исходом;
- в лестнице идеи, шаг 5 («показания»);
- в утреннем отчёте, раздел «Предлагается вывести (решает владелец)», вместе с готовой командой
  `qlab retire <идея> --reason '…'`. Раздел показывает только пары, где открыты обе идеи.

Каждый следующий прогон идеи пересчитывает пометку: перестала совпадать — пометка снимается.
Помечается всегда более новая идея; старая остаётся.

## 3. Реестр сейчас

`scripts/find_duplicates.py` (только чтение) прогоняет обе проверки по всем открытым идеям и печатает
группы. `--mark` дополнительно записывает пометки «по результатам»; статусов не трогает.

    uv run python scripts/find_duplicates.py

## Тесты

`src/qlab/test_duplicates.py`: один и тот же код с теми же числами в разных обёртках; умолчания,
записанные и пропущенные; тот же результат при разных числах; результаты «почти, но не те» (шум,
сдвиг, другая площадка, другое окно, плоский ряд) не помечаются. Плюс по тесту на каждый вход:
исследователь, генератор, программист, `qlab evaluate`.
