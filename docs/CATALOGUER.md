# Разборщик статей: шаг «разобрать» без человека

Решение владельца 2026-10-27: «да, сделай агента для разбора статей в каталог. чтобы шаг
разобрать работал полностью».

## Зачем

Генератор идей собирает стратегию только из чисел, которые стоят в каталоге механизмов
(`docs/MECHANISMS.md`), и у каждого числа записано место в статье. Так генератор не может
выдумать срок или размер выборки. До 27 октября каталог заполнял человек; теперь каждую ночь
одну статью разбирает агент, а проверяет его код.

## Как устроено

1. **Выбор статьи — кодом.** Сначала очередь владельца (`qlab catalogue add <ссылка>`), затем
   статья, по которой разведчик написал черновик карточки, затем лучшая по теме статья ленты
   arXiv, которую разведчик не отверг. Статьи SSRN без владельца не берутся: их текст закрыт
   входом на сайт.
2. **Полный текст — кодом.** PDF скачивается и переводится в текст (`pdftotext`). Если текста
   нет (вход, капча, не PDF), статья откладывается — по одной аннотации каталог не пишется.
3. **Агент** (Sonnet) читает текст, каталог и описание блоков в отдельной рабочей папке и
   пишет один черновик: новый механизм, числа к механизму, который уже есть в каталоге
   (`extends`), или «механизма нет» с причиной. У каждого числа — дословные цитаты из статьи.
4. **Код проверяет черновик:**
   - параметр — из тех, что берут блоки (`docs/BLOCKS.md`);
   - каждая цитата дословно стоит в тексте статьи (переносы строк и слов не мешают);
   - каждое число есть в своей цитате: как написано или срок в сутках — неделя 7, месяц 30
     (правило владельца 2026-10-26), квартал 90, год 365; «weekly» — 7, «квинтиль» — 5;
     процент считается и долей (30% — 0.3). Округлять и выводить числа нельзя;
   - русский текст написан по-русски, без английских торговых слов русскими буквами
     («лонг», «шорт», «кэрри», «моментум», «хедж», «фандинг»…), как требует
     `cards/SCHEMA.md`.
5. **Второй агент-проверяющий** читает статью и черновик и отвечает на то, что код проверить
   не может: число в цитате — это действительно этот параметр, а не размер выборки или дата;
   эффект для этих чисел значим; «суть» не приписывает статье лишнего; механизм не дублирует
   уже записанный. Найденная проблема останавливает статью до решения владельца.
6. **Запись.** Прошедший черновик вписывается в каталог в его формате (новый механизм — перед
   заключительными разделами; числа — строками в таблицу механизма и одной фразой в «Где
   проверено»), затем каталог читается обратно тем же разбором, что у генератора, и запись
   коммитится — только этот файл, локально, без отправки. Если в каталоге есть ваши
   незакоммиченные правки, агент ничего не пишет и ждёт.

Стадия идёт в доле поиска (её бюджет режется первым) и **перед генератором**: механизм,
записанный этой ночью, генератор может собрать этой же ночью.

## Команды владельца

```bash
uv run qlab catalogue list
uv run qlab catalogue add https://arxiv.org/abs/2510.14435
uv run qlab catalogue add https://example.org/paper --pdf ~/Downloads/paper.pdf
uv run qlab catalogue run
uv run qlab catalogue retry arxiv:2510.14435
uv run qlab catalogue reject arxiv:2510.14435 --reason "число не о том"
```

`reject` отменяет запись в каталоге новым коммитом. Настройки — `night/cataloguer.yaml`
(модель, одна статья за ночь, две попытки).

## Первый прогон, 2026-10-27

Статья «Short-horizon mean reversion in cryptocurrency markets» (arXiv 2608.21888): агент
ответил «механизма нет» — в статье разворот на 15-минутных отрезках против издержек сделки,
чего дневные свечи не проверят, и ни одного окна в сутках. 289 тысяч токенов. Каталог не
изменился.
