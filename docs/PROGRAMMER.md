# Агент-программист (2026-10-26)

Владелец, 2026-10-26: «так нам нужен еще один агент - который будет дописывать код если нужно»;
«будет дописывать код если руководитель посчитает что направление - следует проверить»; «да,
делай агента-программиста».

## Зачем

Сегодня проверка идеи владельца по Bv2 («включать страховку почаще») упёрлась в код: окна
сигнала были зашиты во frab константами, и стенд не мог прогнать другие значения. Правку
пришлось делать вручную. Агент-программист делает такие правки сам — когда руководитель
исследований решит, что направление стоит проверить, или когда попросит владелец.

## Откуда берутся запросы

- **Руководитель исследований** пишет в своём блоке указаний `code_requests`: в каком
  репозитории (`frab` — код живых стратегий, `qlab` — блоки стенда), что сделать и зачем. Как и
  пометки исследователю, запрос без цифр: он просит возможность («сделать окна сигнала
  настройкой»), а не значение. Действует только из указаний, которые владелец подтвердил.
- **Владелец**: `qlab code request --repo frab --what "..." --why "..."`.

Очередь — `data/programmer/queue.json`; ночь берёт один запрос (`night/programmer.yaml`).

## Как работает одна попытка

1. Отдельная копия репозитория (git worktree) на новой ветке `agent/<id>` — основная ветка и
   рабочая копия владельца не трогаются.
2. Агент читает код и пишет файлы; запускать ничего не может.
3. Код проверяет:
   - **где писал**: только разрешённые пути. Во frab — только чистые модули стратегий, которые
     гоняет стенд (параметры, сигналы, книги Bv2, trend, XSMOM) и их тесты. Движки, биржа,
     постановка ордеров, база — никогда. В q-lab — только стратегии и блоки, не механизм
     вердиктов;
   - **есть ли тест** среди изменений;
   - **проходят ли все тесты** репозитория в копии, включая проверки на совпадение до бита:
     при настройках по умолчанию поведение не должно измениться.
4. Второй агент-проверяющий читает запрос и изменения; если он называет пробел, запрос
   останавливается и ждёт владельца.
5. Прошедшее изменение коммитится **в свою ветку** и ждёт. Не вышло — следующая ночь пробует
   ещё раз; после двух неудач запрос ждёт владельца.

## Что решает владелец

- `qlab code list` — все запросы и где они;
- `qlab code merge <id>` — слить ветку в основную и отправить на GitHub. Команда ещё раз гоняет
  тесты и откажет, если в основной рабочей копии есть незакоммиченные изменения. Во frab это
  значит: код окажется в main, но на прод не выкатывается — выкатка по-прежнему отдельное решение;
- `qlab code reject <id> --reason "..."` — отклонить, ветка и копия удаляются.

Утренний отчёт пишет раздел «Программист»: что пробовали, чем кончилось, что ждёт решения.
