# XSMOM как известно-ложная стратегия для калибровки (T21)

Дата: 2026-09-21. Правила `2026-09-21.1`, капитал $1 000, снапшот Hyperliquid
2025-01-01 → 2026-09-20, дневные бары — тот же вызов, что и во всех прочих
приёмках M2 (`docs/ACCEPTANCE_M2.md`): `uv run qlab evaluate <spec> --capital
1000 --rules 2026-09-21.1`.

**Смысл задачи инвертирован относительно любой другой.** XSMOM — стратегия,
из-за которой существует весь проект: прежний метод оценил её как прибыльную
(Sharpe 1.80), она пошла на реальные деньги и потеряла −11.19% за 13 недель
(`funding-rate-arbitrage/research/xsmom_live_recon/AUDIT_2026_09.md`).
**Приёмка здесь — отказ фреймворка.** Если он её пропустит — это находка о
самом фреймворке, важнее любого другого результата этой задачи.

Транскрипция — `src/qlab/strategies/xsmom.py` (`XsmomCrossSectionalMomentum`),
каждый параметр процитирован построчно из `frab/strategy/xsmom/{params,
strategy}.py` и `evaluators/{signal,rebalance}.py`; всё, что интерфейс
`target_weights(panel, params)` не может выразить, названо в докстринге явно
(раздел "Left OUT"), а не молча отброшено.

## Итог: два вердикта рядом

| | XSMOM, честный универс (`specs/xsmom.yaml`) | XSMOM, заморож. 32-монетный универс (`specs/xsmom-frozen-universe.yaml`) |
|---|---:|---:|
| trial_id | 1246 | 1247 |
| ann_return_net | **+1.55%** | **+10.96%** |
| sharpe_net | 0.193 | 0.673 |
| max_dd | −16.30% | −13.10% |
| worst_week | −4.48% | −7.53% |
| turnover (годовой) | 23.84 | 27.15 |
| min_capital_usd | $1 776 | $240 |
| n_periods | 627 | 627 |
| инструментов в снапшоте | 222 (обнаружено, universe_complete=True) | 32 (из них 32/32 сконфигурированных присутствуют) |
| **вердикт** | **reject** | **reject** |
| причина | `net_edge_positive`: 0.0155 < 0.04 | `honest_universe`: point_in_time_universe=0 ≠ 1 |

**Фреймворк отверг оба прогона XSMOM.** Приёмка выполнена буквально — но
по-разному интересным образом для двух спеков, см. ниже.

```
ЧЕСТНЫЙ УНИВЕРС (specs/xsmom.yaml)
preflight   venue_supported ✓  data_forward_available ✓
            atomic_execution ✓  capital_fit 1776 <= 120000 ✓
edge        honest_universe ✓  accrual_required ✓
            net_edge_positive 0.0155 >= 0.04 ✗   -- ФАТАЛЬНО, routing: reject

ЗАМОРОЖЕННЫЙ УНИВЕРС (specs/xsmom-frozen-universe.yaml)
preflight   venue_supported ✓  data_forward_available ✓
            atomic_execution ✓  capital_fit 240 <= 120000 ✓
edge        honest_universe 0 == 1 ✗   -- ФАТАЛЬНО, routing: reject
            accrual_required ✓
            net_edge_positive 0.1096 >= 0.04 ✓
```

**Самое важное число этого отчёта:** на замороженном универсе
`net_edge_positive` (планка входа по доходности, 4% годовых) **проходит** —
0.1096 ≥ 0.04. Отказ там держится **целиком** на `honest_universe`. Если бы
этого правила не существовало (а до T-с-номером-меньше-этого его в
фреймворке не было), заморож.-универс XSMOM был бы допущен ровно так же, как
допустила его прежняя система в 2026 году — с тем же самым инструментом
искажения (survivorship). Это не гипотетическое рассуждение о прошлом:
это то же самое число, которое сегодня прошло бы мимо, не будь конкретно
этого одного правила.

## Survivorship-дельта, измеренная нашим же харнессом

| метрика | честный универс | заморож. универс | дельта (заморож. − честный) |
|---|---:|---:|---:|
| ann_return_net | +1.55% | +10.96% | **+9.41 п.п.** |
| sharpe_net | 0.193 | 0.673 | **+0.480** |

Для сравнения — лестница честности из самого аудита (другое окно, другая
методика, но тот же механизм искажения), `AUDIT_2026_09.md`:

```
заявлено при запуске (survivor, окно 2023+)   Sharpe 1.80
− выбор окна (2021+, тот же survivor-универс)  Sharpe 1.21
− survivorship (point-in-time, +28 мёртвых)     Sharpe 0.76   (дельта −0.46)
− funding drag                                  Sharpe ≈0.53
```

Наша дельта survivorship (+0.480 по Sharpe в пользу заморож. универса)
того же порядка, что и аудитная (−0.46 при разворачивании назад к
point-in-time). Число не обязано совпасть — другое окно (2025-2026 против
2021+), другая перебалансировка данных, другой источник (HL здесь и там) —
но порядок величины независимо подтверждает: **survivorship один даёт
Sharpe-эффект около полу-единицы**, не проценты.

## Разбор результата — сигнал / косты / carry

Тот же формат, что и разбор trend в `docs/ACCEPTANCE_M2.md` (сигнал = gross
без костов и funding, косты — по `CostModel`, carry — реализованный funding
из `panel.funding`, сумма — арифметическая, не сложная):

```
ЧЕСТНЫЙ УНИВЕРС
сигнал (gross)    +3.24% годовых
косты              −1.05%
carry (funding)    −0.61%
ИТОГО нетто       +1.58%   (арифметическая сумма; сложная доходность +1.55%)

убыточных дней  261 из 627 (42%)
худший день     −2.66% (2025-04-22)

ЗАМОРОЖЕННЫЙ УНИВЕРС
сигнал (gross)    +13.35% годовых
косты              −1.19%
carry (funding)    −0.93%
ИТОГО нетто       +11.22%   (арифметическая сумма; сложная доходность +10.96%)

убыточных дней  251 из 627 (40%)
худший день     −3.71% (2026-02-24)
```

**В обоих случаях убыток carry, не выигрыш.** Как и trend
(`docs/ACCEPTANCE_M2.md`, "Trend потерял больше половины доходности"), эта
кросс-секционная momentum-книга структурно ПЛАТИТ funding, а не получает
его — то же самое, что нашёл аудит на живых данных: "momentum лонгует то,
что уже выросло — ровно те перпы, где толпа в лонге и платит funding...
momentum на перпах структурно анти-carry" (`AUDIT_2026_09.md`, раздел 3.1).
Три независимых источника (живой P&L, аудит, и теперь наш собственный
харнесс на честных и на заморож. данных) сходятся на одном знаке.

**Косты — не проблема ни в одном из двух прогонов** (−1.05% / −1.19% годовых
при обороте 24-27 — умеренно, сигнал не съедается исполнением). **Разница
между двумя вердиктами целиком в сигнале** (+3.24% против +13.35% годовых
gross) — то есть survivorship искажает именно то число, которое выглядит
как "качество идеи", а не издержки или carry. Это согласуется с выводом
аудита: "Убыток целиком «модельный»: сигнал выбрал то, что упало" — только
здесь это работает в обратную сторону: искусственно ХОРОШИЙ сигнал
заморож. универса — тоже модельный артефакт, а не эдж.

## Сравнение с калибровкой шумом (`docs/CALIBRATION_2026-09-21.1.md`)

Лучший результат из 200 структурно согласованных случайных книг
(dollar-neutral серия): **ann_return_net +4.60%, sharpe_net 0.929**.

| | ann_return_net | sharpe_net | отличим от шума? |
|---|---:|---:|---|
| лучший из 200 случайных книг | +4.60% | 0.929 | (эталон) |
| XSMOM, честный универс | **+1.55%** | **0.193** | **нет — хуже шума по обеим метрикам** |
| XSMOM, заморож. универс | **+10.96%** | **0.673** | доходность выше потолка шума; Sharpe всё ещё НИЖЕ потолка шума |

**На честном универсе XSMOM неотличим от шума, и хуже его лучшего результата
по обеим метрикам разом.** Это количественно подтверждает вывод аудита —
"эджа там не было вовсе, а не «был и выцвел»" (docs/TASKS.md, T21) — причём
на СОВЕРШЕННО ДРУГИХ данных (Hyperliquid 2025-2026, честный универс из 222
инструментов), чем аудит использовал (survivor-универс, окна с 2021). Два
независимых измерения одним и тем же выводом — это не совпадение метода,
это сходящееся свидетельство.

**На заморож. универсе XSMOM превосходит потолок шума по доходности, но не
по Sharpe.** Заявка "10.96% годовых" выглядит убедительно ровно в том виде,
в каком прежний метод дал себя убедить в 2026 году — и именно поэтому это
число проверено дважды (см. следующий раздел), а не принято на веру.

## Проверки, которые я выполнил сам

**1. Еженедельный ребаланс даёт еженедельный оборот, привязанный к
четвергу.** Оборот посчитан напрямую (`weights.diff().abs().sum(axis=1)`),
не предположен:

- честный универс: из 627 баров ненулевой оборот на 234; из них **81 —
  ровно по четвергам** (запланированные ребалансы; из ~90 четвергов в окне
  на 9 книга не изменилась совсем). Оставшиеся 153 — НЕ ошибка в
  планировщике: это `panel.tradeable`, гасящий держащуюся позицию при
  делистинге инструмента ДО следующего планового четверга (см. ниже);
- заморож. универс: 96 ненулевых баров, 81 — по четвергам, 15 — от
  кратких (1-8-барных) исключений по качеству цены
  (`bad_price_bars_excluded`, видны в логе прогона для BNB, DOGE, EIGEN,
  ETH, INJ, LINK, PENDLE, PYTH, SUI, TRX, UNI, XRP, ZRO).
- **Прямая проверка нейтральности по доллару РОВНО в момент ребаланса**
  (не "когда-либо активна", а именно на 90 плановых строках): максимальное
  |сумма весов| = `0.0` (честный) / `5.6e-17` (заморож., плавающая точка) —
  книга дословно dollar-neutral на каждом решении, как и в живом движке
  (`sizing_breakdown`: "Budget is split equally across both sides").

**2. Найдена и задокументирована реальная причина внепланового оборота.**
На честном универсе 213 отдельных событий смены веса на 92 инструментах:
140 — необратимое закрытие при делистинге (тонкие/недолго живущие монеты
вроде HMSTR, ровно тот класс имён, который комментарий в `params.py:12`
называет причиной сужения живого универса до 32 монет), 73 — **временный
флаг `tradeable=False` возвращается в `True`** через день-два (короткая
дыра в качестве котировки, не настоящий делистинг), из-за чего
перенесённый вес молча "переоткрывается" на старом, непересчитанном
значении. Оба эффекта — не гипотеза, а посчитанные числа; оба вписаны в
докстринг `xsmom.py` ("Mid-holding-period delisting or data gaps") как
названное, а не молча спрятанное отклонение от честной транскрипции.
Именно поэтому оборот на честном универсе (23.84 годовых) не в разы ниже
заморож. (27.15) несмотря на впятеро больше инструментов-кандидатов —
большинство "лишних" инструментов слишком коротко живут, чтобы вообще
получить сигнал.

**3. Число инструментов в каждом прогоне.**

- честный универс: 222 инструмента в снапшоте (`universe_complete=True`) —
  то же число, что и в `docs/ACCEPTANCE_M2.md` для trend на этом же окне;
- заморож. универс: снапшот ограничен ровно 32 инструментами
  (`universe_complete=False`, как и должно быть для явного списка), и
  **все 32 из `DEFAULT_XSMOM_UNIVERSE` присутствуют** в снапшоте — 32 из 32,
  ни одного пропущенного тикера.

**4. Числа, показавшиеся убедительными, перепроверены отдельно, не приняты
с одного прогона.** `ann_return_net=+10.96%` на заморож. универсе —
единственное число в этой задаче, которое выглядит "хорошо" — проверено
тремя независимыми способами: (а) через `qlab evaluate` (trial 1247), (б)
пересчётом `compute_metrics` напрямую по тому же `RunResult` вне пайплайна,
(в) декомпозицией на сигнал/косты/carry, сумма которых сходится с итоговым
числом с точностью до сложного/арифметического процента. Ни один
пересчёт не разошёлся с другим.

## Что транскрипция не может выразить (названо, не спрятано)

Полный список — в докстринге `src/qlab/strategies/xsmom.py`; здесь —
сжато:

- **Весь денежный/маржинальный контур** (`budget_cap`, `margin_buffer_
  factor`, `leverage`-как-настройка-биржевой-маржи, резерв 8%/$20) — веса
  это доли ноционала книги, а не доллары; капитал и маржа — забота спека
  (`min_leg_notional`) и `qlab evaluate --capital`, не этой функции;
- **живая просадка деплоя книги при нехватке кандидатов**: транскрибирована
  намеренно (номинальный `k` для размера ноги, но лишь `effective_k` ног
  реально открывается) — это реальная особенность живого движка, а не наша
  добавка, и её легко принять за баг;
- **вся государственная машина** (`NEW→OPENED→CLOSE→CLOSED`, ретраи,
  часовой margin watchdog) — нет аналога в чистой функции
  `(panel, params) → weights`;
- **делистинг/дыра в данных посреди недержания** — см. раздел проверок
  выше; интерфейс может только занулить ногу, а не среагировать раньше
  срока, как живой watchdog;
- **истинная статeful-природа `is_rebalance_due`** — переведена в
  побарную рекурренцию (первый бар обязателен, далее — только по четвергам
  с зазором ≥7 баров), это не приближение, а точный побарный эквивалент
  той же рекурсии, что и в `evaluators/rebalance.py:50-75`.

## Число прогонов

**2 прогона `qlab evaluate` за всю задачу** (trial_id 1246 — честный универс,
1247 — заморож. универс), оба вошли в этот отчёт, ни один не выброшен.
Вся дальнейшая проверка (декомпозиция сигнал/косты/carry, побарная сверка
расписания ребаланса, поиск причины внепланового оборота) сделана прямыми
вызовами `run_backtest`/`compute_metrics` на уже посчитанных данных того же
снапшота — эти вызовы не проходят через `evaluate_spec` и поэтому не пишут
новых `trial`: это пересчёт уже полученного числа, а не новая попытка
оценки стратегии.

Реестр: два новых `spec`/`trial` под существующей graveyard-идеей `xsmom`
(status=decayed, shutdown_cause=false-discovery — тот же ряд, что уже был
в реестре) и под новой идеей `xsmom-frozen-universe` (методологический
форк специально для измерения survivorship-дельты, не самостоятельный
кандидат в воронку — по аналогии с тем, как `xsmom-overlays` уже существует
как отдельная идея-сателлит той же исходной, и с тем, как калибровочные
`noise-*` идеи заведены в `qlab.calibration.run.ensure_noise_idea`).

13 тестов в `src/qlab/strategies/test_xsmom.py` (тот же стиль, что у

# Ревизия 2026-09-21, ночь: фреймворк XSMOM **пропустил**

Проверка отчёта выше дала результат, который его отменяет. Два прогона,
поставленные рядом как «честный универс против замороженного», различаются
**не одним признаком, а двумя**, и вывод про survivorship на них не держится.
Третий прогон, поставленный для разделения этих признаков, фреймворк
**допустил до paper**.

## Почему прежнее сравнение было спутанным

`XsmomParams.compute_k` выводит число ног из размера универса: `k =
universe_len // 3` на сторону. Значит расширение списка кандидатов
автоматически умножает ширину книги:

| прогон | кандидатов | k | ног | min_capital |
|---|---:|---:|---:|---:|
| замороженный | 32 | 10 | 20 | $240 |
| честный | 222 | 74 | **148** | $1 776 |

Книга из 148 ног и книга из 20 ног — разные стратегии, и ровно эта ловушка
уже записана в T18 про trend, где та же идея на 222 инструментах и на 25
потребовала капитала на порядок разного. Разность +9.41 п.п. между этими
прогонами — сумма двух эффектов, а не измерение survivorship. Называть её
survivorship-дельтой нельзя.

## Контрольный прогон: честный универс при живой ширине книги

`specs/xsmom-honest-20legs.yaml` — тот же честный универс из 222
инструментов, но `n_positions: 20`, то есть ровно та ширина книги, которую
живой авто-терциль даёт на 32 монетах. Меняется только состав кандидатов.
Это ручной режим самого живого движка (`XsmomParams.n_positions`), не
придуманный параметр, но и не та конфигурация, которую кто-либо запускал, —
это контроль.

```
trial_id 1248
ann_return_net   +32.17%      sharpe_net     1.042
max_dd           −27.57%      worst_week    −12.65%
skew             +0.337       turnover        41.19
min_capital_usd  $240         n_periods        627

preflight   venue_supported ✓  data_forward_available ✓
            atomic_execution ✓  capital_fit 240 <= 120000 ✓
edge        honest_universe ✓  accrual_required ✓
            net_edge_positive 0.3217 >= 0.04 ✓

routing: paper  (passed and affordable)
```

**Это и есть инвертированная приёмка T21: «Если пропускает — это находка о
фреймворке, и она важнее всех остальных результатов».** Фреймворк
маршрутизировал вариант XSMOM в paper. Ни одно правило не сработало.

Отягчающее обстоятельство: контроль был запущен **один раз**. Перебора не
было, первый же поставленный вариант прошёл. Если бы кто-то искал проходящую
конфигурацию, он нашёл бы её с первой попытки.

## Разбор допущенного результата

```
сигнал (gross)   +29.43% годовых
косты             −1.81%
carry (funding)   +5.21%
убыточных дней  260 из 627 (41%)
```

**Весь результат — десять дней из 627.** Сумма дневных доходностей +0.564;
без пяти лучших дней +0.226; **без десяти лучших дней −0.009**. Полтора
процента наблюдений несут сто процентов результата.

**Carry здесь положительный (+5.21%), а на замороженном универсе
отрицательный (−0.93%).** Это не моментум: на честном универсе книга шортит
монеты с дорогим фондированием и получает за это деньги. Часть «эджа
моментума» — на самом деле carry-сделка, которую стратегия не заявляет.

**Книга состоит из мемкоинов.** Чаще всего удерживаемые имена: GRIFFAIN,
BERA, IP, VVV, MERL, FARTCOIN, RESOLV, ZORA, HYPE, KAITO, GRASS, NXPC, PURR,
SPX, OM. Ранговая корреляция «как часто держим» с годовой волатильностью
+0.465; средняя волатильность удерживаемой книги 129% против медианы
универса 108%. Живой универс XSMOM был курирован фильтром «объём ≥$1M/день»
именно против этого.

Устойчивость к костам проверена отдельно: при проскальзывании 20 б.п. вместо
0.9 доходность +22.2%, при 50 б.п. +7.9%. То есть артефакт костовой модели
это объясняет лишь частично — при $1 000 капитала книга исполнима, проблема
проявится при $120k, где нога в мемкоине становится $6 000.

## Главное: калибровка привязана к форме книги, а не к правилам

Шум был перекалиброван **под эту книгу** (200 испытаний, серия
dollar-neutral, `seed_offset=20000`, trial_id 1249–1448):

| | шум под trend (150 ног) | шум под XSMOM-20 (20 ног) |
|---|---:|---:|
| допущено правилами | **1%** | **26%** |
| медиана доходности | — | −17.11% |
| максимум доходности | +4.60% | **+59.73%** |
| максимум Шарпа | 0.929 | **1.193** |

XSMOM-20 с его +32.17% стоит на **84-м перцентиле** этого шума, Шарп 1.042 —
на **96-м**. Восемь случайных книг из пятидесяти обогнали его по доходности.

**Отсюда вывод, отменяющий формулировку отчёта о калибровке:** «правила
`2026-09-21.1` пропускают шум в 1% случаев» — не свойство правил. Это
свойство пары (правила × форма книги). Для концентрированной книги на
широком волатильном универсе та же планка пропускает шум в каждом четвёртом
случае. Планка в 4% годовых осмысленна для книги со 150 ногами и почти
ничего не отсекает у книги из 20 ног на мемкоинах, потому что разброс
случайного результата там в разы шире.

Отдельная находка про сам инструмент калибровки: **150 из 200 шумовых
испытаний упали** на проверке структурного соответствия — три генератора из
четырёх (`random_weights`, `random_signs`, `bootstrap_time`) переставляют
веса каждый бар и дают оборот в 8.7 раза выше, чем книга, которая держится
неизменной между недельными ребалансами. Выжил только
`shuffled_instruments`, и он же здесь единственно уместный: он сохраняет
форму и тайминг книги и разрушает ровно связь «инструмент ↔ сигнал».
Калибровочный слой не умеет строить шум для стратегий с редким ребалансом —
это его собственный пробел.

## Чего фреймворку не хватило, чтобы не пропустить

1. **Нет правила на концентрацию результата.** Десять дней из 627 несут
   всё — ни одна метрика этого не видит.
2. **Нет правила на ликвидность и ёмкость.** `capital_fit` смотрит только на
   минимальный размер ордера. Книга из мемкоинов проходит его при $240 и
   формально «помещается» в $120 000, где она неисполнима.
3. **Планка доходности не знает о форме книги.** Одно и то же число в 4%
   отсекает 99% шума у широкой книги и 74% у концентрированной.
4. **Дефляция не считает выбор ширины книги испытанием.** `n_positions` —
   документированная ручка живого движка; перебор по ней ничем не отличается
   от перебора параметров, но в счёт испытаний не попадает.

Итого 403, из них 200 не попали в журнал: первая попытка шумового прогона
выполнилась целиком и откатилась на ошибке в коде отчёта, уже после того,
как все 200 оценок были посчитаны. Они объявлены здесь, потому что данные
они видели, и по правилу из `CLAUDE.md` считаются наравне с остальными.

## Что теперь неверно в отчёте выше

- «Фреймворк отверг оба прогона XSMOM» — верно буквально и вводит в
  заблуждение по сути: третий, поставленный правильно, он допустил.
- «Survivorship-дельта +9.41 п.п.» — спутанная величина, не survivorship.
  Разделить её можно только сравнением 1247 и 1248 (обе по 20 ног): +10.96%
  против +32.17%, то есть честный универс здесь **выше** замороженного, и
  знак эффекта противоположен ожидаемому. Отдельная задача.
- «81 из 90 четвергов» — ошибка счёта: срабатывают 90 ребалансов, из них 89
  по четвергам плюс нулевой бар; ровно один четверг пропущен, и правильно
  (с нулевого бара прошёл 1 день из семи). Проверено напрямую.
